# 酷态科 10 号充电器 · 电脑常驻控制台

在 Windows 上通过蓝牙（BLE）直连控制充电器，不经过米家云，也不需要 root。

设备：CUKTECH 10 GaN Charger Ultra（`njcuk.fitting.ad1204`，固件 2.1.2_0073）  
地址：<http://127.0.0.1:8080>

---

## <u>方式一：装安装包（推荐，普通用户用这个）</u>

<u>双击 `CUKTECH-Setup.exe`，勾选需要的东西，点安装。全程不弹 UAC。</u>

- <u>程序装到 `%LOCALAPPDATA%\Programs\CUKTECH`</u>
- <u>数据（配置、历史功率、日志）放 `%LOCALAPPDATA%\CUKTECH`，卸载时可以选择保留</u>
- <u>程序目录里的 </u>**<u>`版本更新说明.md`</u>**<u> 记着每个版本改了什么（v1.3.3 起随安装包附带），  
  想知道"这版好在哪、上版修了什么"直接双击看</u>
- <u>卸载：开始菜单 → CUKTECH → 卸载，或 Windows「设置 → 应用 → 已安装的应用」里卸载</u>

### 第一次打开：扫码连上设备（v1.8.0 起）

<u>装完第一次启动，会先弹一个「连接充电器」窗口，中间是一张登录二维码：</u>

1. <u>手机打开**米家 App**，点右上角「扫一扫」</u>
2. <u>扫窗口里的二维码，扫完**在手机上点「确认登录」**（不点会过期）</u>
3. <u>窗口自动识别出 MAC / TOKEN / BLE KEY 并写成配置，然后自己关掉，控制台直接连上</u>

全程不用手抄、不用命令行、不用点保存。凭据只写到本机 `%LOCALAPPDATA%\CUKTECH\.env`，
不上传任何地方。扫码不成功时，窗口最下面有「扫码不成功？手动填写」，
可以粘贴三项、从文件导入，或用老的控制台方式取码。

> 已经配置过的机器再打开这个窗口不会自动扫码，只显示当前 MAC 和一个「重新扫码」按钮。
> 想要回来看它：托盘右键 →「设置设备凭据…」。

<u>扫码连上之后，日常你只会看到两样东西：</u>**<u>托盘图标</u>**<u> 和 </u>**<u>桌面上的小卡片</u>**<u>。</u>

| 想做什么         | 怎么做                            |
| ------------ | ------------------------------ |
| 打开内部控制台      | 双击桌面/开始菜单图标，或点托盘图标             |
| 打开运行管理（三个开关） | 控制台窗口右下角「⚙ 运行管理」，或托盘右键 → 运行管理… |
| 把窗口收起来       | 点窗口的 X —— 收进托盘，**程序继续在后台跑**    |
| 启停采集服务       | 运行管理里的「采集服务」开关，或托盘右键           |
| 启停桌面卡片       | 运行管理里的「桌面卡片」开关（关掉可省内存）         |
| 开关开机自启       | 运行管理里的「开机自启」开关，或托盘右键           |
| 看当前功率        | 鼠标悬停托盘图标                       |
| 把卡片钉在固定位置    | 卡片右下角**图钉**点一下；再点解除（详见「桌面卡片」）  |
| 彻底退出         | 托盘右键 → 退出                      |

> 装新版会自动停掉早期手动部署的两个计划任务（`CUKTECH充电器控制台`、`CUKTECH桌面组件`），  
> 避免新旧两套同时抢 8080 端口和蓝牙链路。

**它不依赖浏览器**：采集服务是本地后台进程，控制台是内嵌的 WebView2 窗口，  
**所有控制操作都在程序自己的窗口里完成**（v1.1.0 起），关掉浏览器完全不影响。

## 资源占用（v1.2.0 优化后）

任务管理器里会看到 **3 个 `CUKTECH.exe`**，这不是漏杀的重复进程，是设计上的分工：

| 进程                | 作用                 | 私有内存   |
| ----------------- | ------------------ | ------ |
| 管理器（无参数）          | 托盘、控制台窗口、监管另外两个    | ~60 MB |
| 采集服务（`--service`） | 蓝牙长连接 + 本地 8080 服务 | ~37 MB |
| 桌面卡片（`--widget`）  | 桌面上那块小卡片           | ~58 MB |

分开的原因：采集走 asyncio + BLE 长连接，界面走 WinForms 消息循环，放一个进程里任何一边卡住都会拖死另一边。卡片崩了采集还在，采集崩了界面还在。

**另外还会看到一组 `msedgewebview2.exe`**（v1.3.7 起约 12 个），那是控制台和卡片**各自独立**的 WebView2 内核。系统自带的搜索 / 小组件也用同名进程，任务管理器里会混在一起，注意别认错。

> ⚠️ v1.2.0 曾让两个窗口共用一个数据目录，把进程压到 7 个。v1.3.7 实测这个做法会让  
> 第二个窗口的 WebView2 控制器创建失败（`0x8007139F`）→ 控制台一片纯黑，已撤销。  
> 多出来的 5 个进程 / 几十 MB 是买稳定的代价，别再改回去。

合计私有内存约 **338 MB**（不含系统自己的 WebView2；v1.2.0 共用目录时是 310 MB）。

### v1.2.0 前后对比（历史数据，同一台机器、同样开着控制台 + 卡片、启动后静置 90 秒测）

> 这张表是 v1.2.0 当时的优化成绩。其中「共用数据目录」一项已在 v1.3.7 撤销，  
> 现值回落到接近 v1.1.2 那列；保留表格是为了说明当时测过什么，不是当前状态。

| 指标          | v1.1.2    | v1.2.0   | 变化                |
| ----------- | --------- | -------- | ----------------- |
| 进程总数        | 18        | 10       | −8                |
| WebView2 进程 | 12（2 套内核） | 7（1 套内核） | −5                |
| 私有内存合计      | 338 MB    | 310 MB   | **−28 MB（−8%）**   |
| 工作集合计       | 1166 MB   | 791 MB   | **−375 MB（−32%）** |

两个口径差别很大，说明白：**私有内存**是任务管理器"内存"那一列（不含共享 DLL），**工作集**把共享的 Chromium DLL 也算进去、会重复计算。真正体感上"少占了多少物理内存"更接近工作集那一行——省下来的主要就是本来要加载两遍的那套内核。

### v1.2.0 做了什么

| 改动                                                  | 效果                                                            |
| --------------------------------------------------- | ------------------------------------------------------------- |
| 控制台与卡片**共用一份 WebView2 数据目录**（**v1.3.7 已撤销**）        | 当时把浏览器内核从 2 套并成 1 套：12 → 7；后发现会导致控制台黑屏，见 `版本更新说明.md` v1.3.7 节 |
| 追加 Chromium 低内存参数（`--enable-low-end-device-mode` 等） | 渲染进程常驻再降约 20 MB，画质无可感差异                                       |
| 关掉组件更新 / 账号同步 / 后台联网 / Edge 下载与 PDF 悬浮 UI           | 少一堆空转线程（本地单页应用根本用不上）                                          |
| 启动完成后 `gc.freeze()` + 放宽 GC 阈值                      | 内存小幅下降，主要是消掉周期性全量扫描的卡顿                                        |

共用内核有个副作用要知道：**内核进程归"先启动的那个窗口"所有**。实测强制结束管理器进程时，卡片会被新起的浏览器进程接手、画面继续正常刷（已用窗口位图验证），只是控制台自己的渲染进程会一起没了。

### 想再省，两个现成的办法

1. **不用桌面卡片时关掉它**：托盘右键 → 桌面卡片（取消勾选），卡片进程会整个退出，一次性省约 **95 MB** 私有内存（卡片宿主 + 它的渲染进程），下次启动记住这个选择。
2. **只留采集服务**：控制台窗口用 `✕` 关掉后，它的 renderer 也会释放；采集服务单人约 37 MB，是整套里最"划算"的部分（没有它就断了采集）。

再往下就只能改架构了：把卡片做成管理器进程里的第二个窗口，能再省一个约 58 MB 的 Python 宿主，但窗口隔离性会变差（卡片或控制台任何一边卡住会互相拖累），而且桌面贴附那一套要重做，风险不小。

### 试过但走不通的（别再试）

把控制台收进托盘后用 `CoreWebView2.TrySuspendAsync()` 挂起渲染进程——思路正确，实测在本项目跑不通：WinForms 版控件没有 `CoreWebView2Controller` 属性，改设控件的 `Visible = False` 会让控件直接进入 disposed 状态，随后调用必抛 `0x8007139F (ERROR_INVALID_STATE)`。详见 `GitHub\desktop\wv2env.py` 顶部注释。

## 桌面卡片

一块 324×216 的深色圆角小卡片，常驻桌面：

- **固定在桌面**（默认，说的是层级，和上面「固定位置」锁坐标是两件事）：卡片是**桌面窗口的子窗口**，和壁纸、桌面图标、腾讯桌面整理的格子处在同一层。看着桌面时它在，一开浏览器/文档就被盖住，不挡事；按 `Win+D` 显示桌面**它不会消失**（v1.3.4 修的，之前会被桌面层整个盖掉）
- **拖动**：按住顶部「CUKTECH 10 Ultra」那一行拖走，松手位置自动记住（存在 `GitHub\data\widget_window.json`）
- **固定位置**（v1.3.0 新增）：点右下角那枚**图钉**，卡片就钉在当前坐标——顶部拖动区立刻失效（拖不动也变不出手型），别人（或系统）把它挪走，**1~2 秒内自动弹回原位**；图钉变青色＝已固定，再点一下解除。状态写进 `widget_window.json` 的 `pinned` 字段，**重启、重新登录、切显示方式都还钉着**
- **点端口**：点 C1 / C2 / C3 / A 任意一格，直接开关该端口
- **切模式**：底部四个胶囊（AI / 数码 / 单口 / 均衡）点一下即切换
- **收起**：点右下角 `✕` 收进托盘；托盘闪电图标单击可再弹出
- **完整面板**：点「完整面板 ↗」或双击卡片空白处，拉起内部控制台窗口（不再开浏览器）
- **不占任务栏**（v1.3.1）：卡片是桌面挂件，任务栏和 Alt+Tab 里都不会出现它；任务栏上那个  
  CUKTECH 按钮只属于**控制台窗口**，窗口收进托盘它就跟着消失，再打开又回来
- **托盘**：图标随功率变色（青 → 黄 → 橙），鼠标悬停显示当前总功率，右键可开关端口、切模式、**切换显示方式**、退出

### 显示方式（托盘右键 → 显示方式）

| 方式        | 效果                                                 |
| --------- | -------------------------------------------------- |
| **固定在桌面** | 桌面层子窗口：和桌面图标同层，所有应用窗口之下。不挡事，`Win+D` 也不消失。想随时看功率就选它 |
| **悬浮置顶**  | 永远压在最上层，盖住别的窗口。适合边充边盯功率                            |

选过一次会记住，下次启动沿用。

> **v1.3.4 更正了一个旧结论**：v1.3.0 时试过 `SetParent` 到桌面，结论是「什么都不渲染」，  
> 于是退而用「z-order 紧贴桌面之上」。但那个做法在按 `Win+D` 时会被桌面层整个盖住  
> （窗口 `IsWindowVisible` 仍是 True，屏幕上却只剩图标，看门狗根本发现不了），  
> 圆角也因为窗口底色被补成直角。
>
> 2026-11-04 重新实测，`SetParent` 这条路是通的，当初失败是因为**漏了配套动作**：  
> 只 `SetParent` 不改样式，DWM 仍按顶层窗口处理，画面就是空的。必须一起做三件事：  
> ① 样式从 `WS_POPUP` 换成 `WS_CHILD`；② `ShowWindow(SW_SHOWNOACTIVATE)` 重新显示；  
> ③ 把高度抖 1px 再抖回来，逼 WebView2 重新合成（否则画面停在挂父前那一帧）。
>
> 还有两个反直觉的点：父窗口要选 **Progman**（挂到 `SHELLDLL_DefView` 会被 `SysListView32` 盖住）；  
> 并且**不能带 `WS_EX_NOACTIVATE`**，否则窗口拿不到焦点，WebView2 会把系统鼠标消息全丢掉，  
> 表现是「卡片看得见但点不动」。
>
> 切换「悬浮置顶」时会 `SetParent(None)` 脱出桌面层，否则它永远被桌面窗口的层级管着。

技术上是 pywebview 套系统自带的 Edge WebView2 内核，不打包浏览器，所以进程只有几十 MB。卡片和后台服务是两个独立进程：卡片关掉不影响采集，服务挂了卡片会显示「控制台未响应」并在恢复后自己接上。

## 内部控制台（v1.1.0 起，不再跳浏览器）

以前点「打开网页控制台」会拉起系统浏览器，控制到一半切走再切回来很容易断片。  
现在完整控制界面直接装进程序自己的窗口里：**同一个页面、同一个源，只是不再离开应用**。

### 怎么用

| 入口                 | 结果                                        |
| ------------------ | ----------------------------------------- |
| 双击桌面 / 开始菜单图标      | 直接打开内部控制台（主窗口，1160×820，可最大化）              |
| 托盘图标双击 / 右键 → 控制台  | 同上；已打开时是「显示/隐藏」开关                         |
| 托盘右键 → 运行管理        | 亮出控制台窗口并展开右下角「运行管理」浮层（服务 / 卡片 / 开机自启三个开关） |
| 桌面卡片点「完整面板 ↗」或双击卡片 | 拉起内部控制台（不再开浏览器）                           |
| 托盘右键 → 重新加载控制台     | 窗口白屏 / 页面卡住时强制重新载入（采集服务不动，只在窗口里重开一次页面）    |

### 窗口里有什么（= 浏览器里的全部）

- **总功率能量条**：顶部实时流动条 + 数值，随功率变色
- **四口实时数据**：C1 / C2 / C3 / A 各自的功率、电压 / 电流、功率条
- **端口开关**：每口一个开关，点一下立刻生效并回报结果（带 toast 提示）
- **倒计时**：每口 15 / 30 / 60 分钟快捷按钮 + 自定义分钟数
- **设备设置**：场景模式（AI / 数码生态 / 单口 / 均衡）、息屏时间、语言、USB-A 小电流常开、  
  空闲息屏、屏幕方向锁 —— 全部分段按钮 / 开关，和网页端一模一样
- **连接控制**：连接设备 / 断开、右上角刷新（重读设备设置）
- **历史曲线**：日期 / 端口 / 粒度 三项切换；默认「今天 + 按分钟」，同一张图里叠两条线 ——  
  所选端口的**功率**（绿）和全场**总功率**（蓝），看图就知道这一口占了总功率多少。  
  Chart.js 已随程序打包（`web\vendor\`），**断网也能画**
- **实时同步**：走的是同一条 WebSocket（`/ws`），设备状态变化 0.5 秒内推到界面；  
  断开时顶部弹「连接已断开，正在重连…」，恢复后自动接上

### 运行管理浮层

控制台窗口**右下角**有一个「⚙ 运行管理」小按钮，点开就是一个浮层：

- 顶部：标题右侧的 **版本号**（如 `v1.7.0`，来自 `desktop\version.py`，和日志里的一致）+ 当前总功率 + 连接状态徽标（每 2 秒自动刷新）
- 三个开关：**采集服务**（关掉后所有控制失效）、**桌面卡片**、**开机自启**
- 一行 **版本更新**：显示当前版本，有新版本时出现「立即更新」按钮（见下一节）
- 两个按钮：**数据目录**（资源管理器打开）、**退出**（整个程序退出）
- 底部：数据目录路径

> v1.6.0 起「自动启动」搬到了控制台的 **设备设置 → 场景设置**，浮层里只剩纯运行管理
> （服务 / 卡片 / 自启），别在浮层里找它了。

> v1.3.0 起**移除了「浏览器打开」按钮**：界面只走应用自己的控制台窗口，  
> 程序也不会再主动拉起系统浏览器。报问题时请提供 `logs\manager.log` / `console.log`，  
> 需要看网页的话自己手动开 `http://127.0.0.1:8080` 即可（通道还在，只是不再自动跳）。

浮层是**注入到页面里的**，不是第二个窗口——所以它跟着页面一起加载、跟着页面一起消失，  
不存在「窗口在、页面死」这种半残状态。它由本地服务下发（`/console.js`），  
页面自己 `<script>` 引入；Python 只负责告诉它「该亮出来了」。

用**普通浏览器**打开 `http://127.0.0.1:8080` 时不会有这个按钮（那边没有程序接口，  
按了也没用），看到的就是原来那个干净的控制页面。


### 检查更新（v1.7.0 新增）

程序会自己看有没有新版本，**不需要你手动去问**。

- **什么时候查**：启动后约 40 秒查一次，之后 24 小时内不再查（避免每次开程序都打网络）。
  想立刻查，点浮层里的「检查」或托盘右键的「检查更新…」。
- **在哪看**：浮层里的「版本更新」一行，托盘菜单里也会显示成 `↑ 有新版本 v1.7.1…`。
- **怎么装**：点「立即更新」→ 自动下载（有进度条）→ 校验安装包 → 程序自己关掉 → 静默装好 → 自动重新打开。
  你手动改过的设置、取好的凭据、历史功率数据都保留。

几条设计上的取舍，遇到问题先看这里：

| 情况 | 表现 |
| --- | --- |
| 没网 / 清单打不开 / 被墙 | **什么都不弹**，只往 `logs\manager.log` 记一行，下次再试 |
| 安装包校验失败 | 删掉包、提示「校验失败」，**不会安装**；程序照常用 |
| 磁盘空间不够 | 下载前就拦住，提示需要多少空间 |
| 更新失败 | 安装包留着，浮层里点「重试」；也可去 Releases 页手动下载 |
| 你关掉了开机自启 | 更新**不会**把它重新打开（v1.7.0 修的问题） |
| 你删了桌面快捷方式 | 更新**不会**把它重新建出来 |

> **v1.6.0 及更早的版本收不到更新**——那时的程序里没有这条通道。  
> 需要手动装一次 v1.7.0，之后才能自动更新。


### 自动启动（v1.3.2 新增，v1.3.3 调整判定，v1.3.6 可自定义时间窗与端口，**v1.6.0 搬到设备设置**）

早上开机后经常发现有几个口是关着的（前晚手动关过、或设备记着上次的状态），  
这个自动化就是补这一步：**在所设范围内，只要有一个口是关的，就把它打开**；已经开着的不用管。

**在哪设**：控制台页面 → **设备设置** 卡片 → **场景设置** 分组里的「自动启动」。  
和「场景模式」并排成一条列表项，右侧是开关；打开后开关下面才会展开时间窗和端口范围。  
改完立即生效、立即存盘，没有额外的保存按钮。

> v1.6.0 之前它在「运行管理」浮层里（当时叫「自动开端口」）。规则逻辑一个字没改，
> 所以 `logs\manager.log` 里的日志前缀仍然是 `[自动开端口]`，方便对着旧日志排查。

| 选择框     | 可选值                                    | 说明                               |
| ------- | -------------------------------------- | -------------------------------- |
| **时间窗** | 任意 `HH:MM – HH:MM`（默认 `07:00–12:00`）   | 只有在这个时段内启动程序才会检查。结束时间按**整分钟含进去** |
| **端口**  | **全部充电口** / **C1** / **C2** / **C3** / **A** | 五种互斥，选哪个就只动哪个；其余口即使是关的也不碰        |

**端口范围怎么影响行为**

| 模式         | 检查范围             | 会动的口                   | 「今天做过了」的判据    |
| ---------- | ---------------- | ---------------------- | ------------- |
| 全部充电口      | C1 / C2 / C3 / A | 四个口里没开的全部打开            | 复核到四口全开才占名额   |
| 单个端口（如 C3） | 只看 C3            | **只开 C3**，另外三个口即使关着也不碰 | 复核到 C3 已开就占名额 |

单口模式下别的口关着不算失败——我们本来就不该碰它们，复核也只看所选的那个口。

**触发条件（只有一处，不是定时器）**

| 条件 | 说明                                                             |
| -- | -------------------------------------------------------------- |
| 开关 | 设备设置 → 场景设置里的 **自动启动** 开关（默认开着）。关掉后启动时完全不检查，设置存在 `data\autoport.json` |
| 时机 | **程序启动时**判断一次（含开机自启的 `--silent`）。不是整点触发，也不轮询                   |
| 时间 | 启动那一刻必须落在**所设时间窗**内，否则只写一行日志、什么都不做                             |
| 设备 | 采集服务要先连上充电器（最多等 3 分钟）；连不上就记一条「本次未执行」                           |
| 当天 | 当天**已经真的开过口**就不再重复（反复重启不会重复发蓝牙命令）                              |

**「算一次」的判据（v1.3.3 调整，沿用至今）**

不是"连上设备、检查过就算"，而是**本次真的开过口**才算：

| 启动时的实际情况             | 是否占用当天名额            |
| -------------------- | ------------------- |
| 所选端口本来就全开，一个写命令都没发   | **不占**——当天再启动还会再查一次 |
| 有未开的口，本次补开并复核到所选端口全开 | 占用——当天不再自动跑         |
| 读不到位图 / 没连上设备 / 补开失败 | 不占——当天重启会重试         |

这样"早上检查时恰好全开、下午你手动关了一个"就不会被漏掉：当天再启动程序它会自己补开。  
代价是端口长期全开时每次启动多读一次位图（一次蓝牙读，几十毫秒），这个取舍是故意的。

**时间边界**：`开始时间 ≤ 现在 < 结束时间 + 1 分钟`

- **含开始**：`07:00` 起就能触发；
- **含结束整分钟**：默认的 `12:00` 表示 12:00:00–12:00:59 期间启动仍然触发，12:01:00 起不再触发。  
  这条规则没因为改成可配置而改变，只是把 7 / 12 换成了你设的值。
- 开始时间等于结束时间 = 只在那一个整分钟内生效；
- 开始时间晚于结束时间会被拒绝（页面上会弹出提示，不会存进去）；
- 时间窗之前启动不触发——按设计「只在启动时判断」，不会到了点再补做。  
  真需要现在就补，把时间窗临时改成「包含当下」，或在设备设置里开关一次自动启动。

**检测范围**：只看端口**使能位图**（设备属性 `piid=16`，bit0=C1、bit1=C2、bit2=C3、bit3=A，`0x0F` 表示四口全开）。  
它跟「有没有在充电」是两件事——`ports[*].active` 表示端口上有没有负载，  
关掉的口 active 同样是 false，拿它判断会把四个口全当关闭。

**执行逻辑**

1. 起点校验：时间窗 → 当日是否已「开过口」；
2. 等采集服务 `READY`（自动触发时，等待期间出了时间窗就放弃）；
3. `POST /api/refresh` 让服务从设备重新读一遍位图（不用缓存，避免把已开的看成关的）；
4. 在**所选范围**内算出未开启的端口；全开则直接结束，一个写命令都不发，**也不占当日名额**；
5. 对未开启的端口逐个 `POST /api/port {port, action:"on"}`，已开启的完全不动；
6. 再读一遍位图复核，**所选端口全开**才记下当日已完成；没全开则记 error，下次启动重试。

日志（`%LOCALAPPDATA%\CUKTECH\logs\manager.log`）：

```
[自动开端口] 触发：07:12:31（窗口 07:00–12:00，含两端；范围 全部充电口）
[自动开端口] 位图=0x0B，全部充电口 内未开启：C3，开始逐个开启
[自动开端口] C3 已开启
[自动开端口] 今日 07:12:34 自动检查：C3 未开 → 已全部开启（0x0B→0x0F），复核 全部充电口 全开
```

单口模式（范围 C3）只会下发一条命令，复核文案是「复核 C3 全开」：

```
[自动开端口] 触发：07:12:31（窗口 07:00–12:00，含两端；范围 C3）
[自动开端口] 位图=0x0B，C3 内未开启：C3，开始逐个开启
[自动开端口] 今日 07:12:34 自动检查：C3 未开 → 已开启（0x0B→0x0F），复核 C3 全开
```

没触发时只有一行：`[自动开端口] 不在 07:00–12:00 时段（现在 13:02:11），本次不执行`（时段是配置值）。  
所选端口本来就全开时多一句「无需处理，不占今日名额」：

```

```

浮层那行文字会显示最近一次结果（开过几个口 / 已全开 / 不在时段 / 已关闭 / 未连上设备）。

- **开关**：默认开。关掉后启动时不再检查，手动「立即」仍可用（那是你明确点的）。  
  重新打开时如果当前正好在时间窗内且今天还没成功开过口，会立刻补做一次，不用等下次开机。
- **「立即」按钮**：手动强制检查一次，忽略时间窗和「当天已开过口」的限制，用来补做或验证。  
  它同样遵守当前选的端口范围。

> 实现位置：`GitHub\desktop\autoport.py`（设置 + 规则 + 执行）、`desktop\manager.py`

> 配置文件长这样（`%LOCALAPPDATA%\CUKTECH\data\autoport.json`）：
>
> ```json
> { "enabled": true, "start": "07:00", "end": "12:00", "ports": "all" }
> ```
>

### 服务没起来的时候

窗口不会白屏，会显示一个引导页：闪电图标 + 三步进度（启动采集服务 → 等待本地接口 → 载入界面），  
超时或失败时给出「重试 / 重启采集服务 / 运行管理」三个按钮。  
引导和导航都由主程序驱动，页面本身不发网络请求，所以不存在跨源失败。

### 浏览器端还保留什么

| 能力                              | 为什么保留                              |
| ------------------------------- | ---------------------------------- |
| `http://127.0.0.1:8080` 完整网页控制台 | 手机 / 平板在同一台电脑上浏览时用；多显示器分别盯不同页面     |
| `/widget?shell=1` 紧凑版           | 换设备或做嵌入时用                          |
| `/api/*` + `/ws`                | 第三方脚本、自动化、Home Assistant 之类接进来     |
| `/vendor/*`                     | 网页端自己的静态资源（Chart.js），只读白名单，带目录穿越防护 |

也就是说：**日常用不再需要浏览器，但浏览器那条通道一个字没动。**

**读**：四个端口（C1/C2/C3/A）各自的电压、电流、功率、当前协商协议；总功率；历史曲线（本地 SQLite，`GitHub\data\history\`）。

**改**：场景模式（AI / 数码生态 / 单口 / 均衡）、每个端口独立开关、逐口协议开关（PD / PPS / UFCS / SCP）、每口倒计时、USB-A 小电流常开、息屏时间、语言、空闲息屏、屏幕方向锁。

**做不到**：指定 PD 输出电压电流档位。协商是充电器和被充设备之间的事，软件只能开关某类协议。

## 三个必须知道的前提

1. **手机米家会显示离线**。充电器固件只接受一条 BLE 链路，电脑连着，手机就连不上；你打开米家，电脑端就会断（15 秒内自动重连回来）。
2. **电脑睡眠 = 断链**。当前交流电下 60 分钟无操作会睡眠（`powercfg` 实测 0x0e10 = 3600 秒）。唤醒后会自动重连。要真正 7×24 就自己把睡眠设成「从不」——这个我没擅自改你的电源计划。
3. **不要在多台设备上同时连**。米家、这个控制台、别的脚本，同一时刻只能有一个。

## 排障

| 现象                                      | 原因 / 处理                                           |
| --------------------------------------- | ------------------------------------------------- |
| 网页打不开                                   | 托盘右键退出后重新打开程序；或看 `GitHub\logs\console.log`         |
| 状态一直 DISCONNECTED                       | 手机米家还占着连接；或充电器被拔了电源。日志里会打印每次重试的失败原因               |
| `Device with address ... was not found` | 见下一节，日志里会自动附一份扫描诊断                                |

| 认证失败                                    | token 变了。在米家里重新绑定设备会换 token，需要重跑 `取硬件码.bat`（或托盘「设置设备凭据」重新粘贴） |


### `Device with address 3C:CD:73:30:A0:3A was not found` 怎么查（v1.3.0）

这句话是 Windows 蓝牙栈（WinRT `FromBluetoothAddressAsync`）在「按地址找不到设备」时抛的，  
它把四种完全不同的情况混成了一句，所以光看它没法判断：

| 真实原因                  | 判别依据                        |
| --------------------- | --------------------------- |
| 充电器没通电 / 待机后停了 BLE 广播 | 扫描结果里**没有**这台设备，但能扫到别的设备    |
| 已被别的主机连着（手机米家、另一个脚本）  | 同上：设备被占用时通常不广播              |
| 配置里的 MAC 过期（设备换了地址）   | 能扫到**名字带 njcuk** 的设备，但地址对不上 |
| 蓝牙适配器关了 / 驱动异常        | 一台都扫不到                      |

v1.3.0 起，采集服务在连接失败时会自动做一次 6 秒扫描，把结论写进 `logs\console.log`：

```
[auto] 连接失败(1/6): Device with address 3C:CD:73:30:A0:3A was not found.
[diag] 扫描 6s，可见 BLE 设备 8 个
[diag]   66:49:2C:D5:E8:48  RSSI=-59  NZDKWL2Kw3jpVEr7CjoPuHk1A
[diag] 结论：附近能扫到 8 台设备但没有 3C:CD:73:30:A0:3A：充电器多半没通电、
       待机后停了广播，或已被手机 App 连着（这两种都不会广播）
```

另外，6 次快速重试用完后**每隔 1 分钟仍会重试一次并记录结果**（以前是静默重试，  
日志看着像卡死），每 2 分钟附带一次诊断。

按日志分流：

- 提示「没有目标地址」→ 先给充电器通电 / 插上负载唤醒，关掉手机米家，然后重启采集服务  
  （运行管理浮层里关一下「采集服务」再打开）
- 提示「同厂商地址不同」→ 地址变了，重跑 `取硬件码.bat`，或在「设置设备凭据」里粘新的三项
- 提示「一台都扫不到」→ 蓝牙适配器问题，先查系统蓝牙开关/驱动
- 能扫到但连不上 → 多半还被别的主机占着，等 15 秒看自动重连  
  | 连上但读不到端口数据 | 端口上没插设备时就是 `null`，正常 |  
  | 卡片一片空白 / 白框 | 系统缺 WebView2 运行时。Win11 自带；缺的话去微软官网装「WebView2 Runtime」 |  
  | 卡片显示「控制台未响应」 | 后台服务没起。打开控制台程序（`CUKTECH.exe`）即可，卡片会自己恢复 |  
  | 卡片拖不动 | 只能按住顶部标题那一行拖（其余区域留给点端口和切模式） |

日志：`GitHub\logs\console.log`（服务）、`GitHub\logs\widget.log`（卡片，超过 5MB 自动清空）

    ├── widget_app.py 桌面卡片（pywebview 窗口 + pystray 托盘）
    ├── widget.html   卡片界面（也用于浏览器预览：/widget?preview=1）
    ├── .venv\
    ├── data\history\ 历史数据
    ├── data\widget_window.json  卡片上次位置
    └── logs\         console.log / widget.log
```

## 关于 `cuktech.py`

上游项目只读环境变量、不会加载 `.env`，Web 端还要手动点「连接」，不适合常驻。这个薄封装补了四件事，**没有改上游任何一行代码**：

1. 读 `GitHub\.env` 注入环境变量（真实环境变量优先，方便临时覆盖排障）
2. `--open`：~~服务起来后自动开浏览器~~ —— **v1.3.0 已移除**，界面统一走应用自己的控制台窗口，服务只输出日志
3. `--log`：把输出写进日志；`pythonw` 下没有 stdout，上游会直接崩，这里先把流换掉
4. `CUKTECH_AUTO_CONNECT=1`：启动即连 + 断线看门狗（你在网页上主动点「断开」后它不会抢回来）

CLI 用法与上游一致：`GitHub\.venv\Scripts\python.exe cuktech.py status`


## 开发者：改完代码怎么重新出安装包

```bat
cd GitHub
.venv\Scripts\python.exe build_installer.py
```

三步走：PyInstaller 打应用（`CUKTECH.spec`，onedir）→ 压成 `build\payload\payload.zip`  
→ 用**系统 Python 3.12** 打安装器（`installer\installer.py`，onefile）  
→ 产出 `GitHub\dist\CUKTECH-Setup.exe`。

**出包之后不用再手动收尾**（v1.5.0 起自动化）：`build_installer.py` 会把产物同时写进
`安装包\CUKTECH-Setup_v新版本号.exe`（档案库，旧的自动挪进 `安装包\历史\`，只增不改）
和 `分发\CUKTECH-Setup_v新版本号.exe`（只留最新一版，旧包**确认已入档才删**），
并把 `版本更新说明.md` / `使用说明.md` / 取码工具同步到 `分发\`。
这三步以前靠「文档里写一句、人记住」，结果 `分发\` 里长期躺着上一版安装包、
说明文档还停在 v1.3.7。

**发版前先写更新说明**：改完代码在 `GitHub\版本更新说明.md` 顶上新增一节（版本号、日期、  
改了什么、为什么改），再改 `desktop\version.py` 的 `VERSION`。构建时这份 md 会用  
`--add-data` 塞进安装器，装完由 `installer.copy_changelog()` 复制到程序目录根下，  
文件名就叫 `版本更新说明.md`。它不进 `payload.zip`——那是运行时资源，文档没必要混进去。

### 版本号规则（今后强制遵守）

**只要功能有任何变化，就必须升版本号**——新增功能、改变行为、修 bug，以及界面 / 交互的
调整都算。不允许「代码改了、版本号没动」：那样会出现「装的到底是哪一版」说不清、
出了问题也没法对照日志和更新说明的情况。

版本号唯一来源是 `GitHub\desktop\version.py` 的 `VERSION`，遵循语义化版本 `主.次.修`：

| 段位 | 什么时候 +1 | 例子 |
| --- | --- | --- |
| **主版本** | 不兼容的结构性变化：配置格式、数据目录、对外接口变了，老配置 / 老数据不能直接用 | v1.x → **v2.0.0** |
| **次版本** | 新增功能、行为或界面有明显变化（用户能感知到「不一样了」） | v1.4.1 → **v1.5.0** |
| **修订号** | 纯修复：不加功能、不改界面，只把原来该对的改对 | v1.4.0 → **v1.4.1** |

- 次版本 +1 时修订号归零；主版本 +1 时次版本和修订号一起归零。
- 一次改动里既有新功能又有 bug 修复，取高的那一段（→ 次版本）。
- 纯文档、注释、构建脚本的改动可以不升版本号；**只要动到 `web\` / `desktop\` /
  `src\` / `widget.html` 里用户看得见的行为，就必须升**。

**每个版本要手工改这四处**（漏一处就算没发完）：

1. `GitHub\desktop\version.py` → `VERSION`（唯一来源）
2. `GitHub\版本更新说明.md` → 顶部新增 `## vX.Y.Z（YYYY-MM-DD）` 一节
3. `GitHub\installer\installer.py` → `VERSION`（构建时会被覆盖，但兜底值也要跟上）
4. `使用说明.md` / `README.md` 里写死的安装包文件名

另有**两处派生版本号，构建时自动同步，不要手改**（手改下次出包会被覆盖回去）：

- `GitHub\pyproject.toml` 的 `version` —— 这是 **Python 包的元数据**，`pip show
  cuktech-ble-controller`、`importlib.metadata.version(...)` 读的就是它。它不参与界面
  显示、也不进安装包，所以以前长期停在 `0.1.0` 没人发现；但它决定 `pip install -e .`
  装出来的是什么版本，做集成 / 写脚本的人会看，因此纳入统一体系。
- `GitHub\src\cuktech_ble_controller\__init__.py` 的 `__version__` —— 运行时读版本用。

`sync_project_metadata()` 会在出包前把这两处改写成 `desktop\version.py` 的值。

`build_installer.py` 出包前会跑 `assert_version_consistency()` 把这些核一遍：
更新说明里没有当前版本号、文档里的安装包名和当前版本对不上、或者派生版本号没跟上，
**直接中止出包**。
所以以后漏改是构建失败，而不是悄悄发出去。文档里引用**历史版本**的地方不用改。

几个已经踩过的点：

- 安装器界面是 tkinter 写的，而 `GitHub\.venv` 的 3.13 是精简环境**没带 tk**，  
  所以安装器必须用系统 Python 打包，不能沿用 venv 的 pyinstaller
- **构建缓存必须放到临时目录**（脚本里已经这么做）：PyInstaller 开始前会递归清空自己的  
  workpath，本机安全策略对「一轮命令里删超过 50 个文件」会直接拦，表现为构建  
  「命令失败（1）」或者**静默停在第 2/3 步**。同理，旧的 `dist\CUKTECH` 和  
  `dist\CUKTECH-Setup.exe` 都是**改名挪开**而不是删除（`_prev_*`），  
  `payload.zip` 用 `ZipFile(mode="w")` 原地截断重写。
- **旧产物现在会自动收尾**（v1.3.3）：构建成功后 `prune_old_outputs()` 把 `_prev_*`  
  和 `_prev_setup_*.exe` 清到各留最近 1 份，构建失败时一个都不碰（还能回退）。  
  之前只挪不删，一天下来堆了 **43 项 / 2.02 GB**。  
  **v1.5.0 起改成逐个文件删**（`_remove_tree`）：`shutil.rmtree` 一次性删 140+ 个文件会  
  触发本机安全策略，**直接把进程掐掉**（不是抛异常），于是「构建成功但没归档」——  
  因为 prune 排在归档前面被掐了。逐个 `os.remove` 不会触发，且清理挪到归档之后。
- 打出来的 exe 是 windowed 模式，`sys.stdout` 是 `None`，入口 `main.py` 里必须先换掉流，  
  否则任何一句 print 都会 AttributeError
- 安装器拉起应用时要用 `DETACHED_PROCESS`，否则安装器进程一退出会把刚启动的应用一起收走
- **浮层等 js_api 要用轮询，不能只听 `pywebviewready` 事件**（v1.1.1 修的）：pywebview 注入  
  `window.pywebview` 的时机和页面导航完成有竞争，事件早于浮层脚本注册监听就永远等不到，  
  表现是控制台右下角**没有 ⚙ 运行管理按钮**、日志里缺「控制台页面就绪（浮层回报）」这一行。  
  现在改成每 250ms 探一次 `window.pywebview.api`，最多 30 秒；30 秒仍没有才判定为  
  「在普通浏览器里打开」，把浮层整块撤掉。另外 6 秒还没拿到 api 会往 console.log 写一笔  
  `API-MISSING`，以后遇到这问题不用再猜。
- 用 `taskkill /F` 强杀应用后**立刻**重启，WebView2 的用户数据目录还被上一个进程占着，  
  新实例的页面会卡在「HTML 拿到了、脚本不执行」，日志里表现为只有 `GET /` 和  
  `GET /console.js` 之后一片安静。等 3 秒再启动就正常。


### 窗口黑屏 / 卡片白块（v1.1.2 已修，留档备查）

**症状**：窗口和标题栏都在，页面也确实加载了（日志有 `GET /`、`/console.js`、WebSocket 已连接、  
「控制台页面就绪（浮层回报）」），但客户区永远是一块纯背景色（控制台 `#0f1116`、卡片白或黑），  
一点内容都不显示。

**根因**：WebView2 的**渲染进程沙箱在这台机器上初始化失败**，渲染进程被 Chromium 自己的 CHECK  
打死，所以 DOM 起来了却没有一帧被画到窗口上。三条证据：

1. `%LOCALAPPDATA%\CUKTECH\data\webview2-console\EBWebView\Crashpad\reports\` 每次启动都多出  
   几个 `.dmp`；解析 minidump 是 `0x80000003`（STATUS_BREAKPOINT）落在 `msedge.dll+0xb47d1bd`；
2. 同一台机器上系统自带的 WebView2 应用（搜索、小组件）**一个崩溃转储都没有** → 运行时没坏；
3. 用 DevTools 的 `Page.captureScreenshot` 让浏览器自己截图，**界面是完整的**（带实时功率）  
   → 渲染管线正常，缺的是"送到窗口"这一步。

**修法**：给 WebView2 追加 `--no-sandbox`（`desktop/wv2env.py`）。修完实测：崩溃转储 0 个、  
窗口颜色数从 1 变成 2756、卡片 818，功率数据实时刷新。  
⚠️ 只关 GPU 沙箱（`--disable-gpu-sandbox`）实测会让 WebView2 直接起不来，别用那条更窄的开关。  
本程序只加载 `127.0.0.1:8080` 上的自有页面，关渲染沙箱的暴露面可以接受。

**怎么自查（不用猜）**

```bat
:: 1) 看有没有崩溃：数量不减 = 还在崩
dir /b "%LOCALAPPDATA%\CUKTECH\data\webview2-console\EBWebView\Crashpad\reports\*.dmp"

:: 2) 让应用把"浏览器自己画的画面"存成图（最硬的证据，和窗口显不显示无关）
set CUKTECH_SNAPSHOT=1
"%LOCALAPPDATA%\Programs\CUKTECH\CUKTECH.exe"
:: 出图位置：%LOCALAPPDATA%\CUKTECH\logs\console-shot.png
```

- 图里有完整界面 + 窗口是黑 → 问题在"渲染结果没送到窗口"（沙箱 / 合成层），不是页面本身
- 图本身是空白 → 渲染管线或页面自身的问题（这时去看 `logs\console.log` 的报错）
- 注意 `console-shot.png` 只能由 `on_overlay_ready` 触发，得等页面就绪那行日志出现后才生成

### 排障用的小开关

| 开关                                             | 作用                                                                                     |
| ---------------------------------------------- | -------------------------------------------------------------------------------------- |
| `CUKTECH_DEBUG_PORT=9333`                      | 给控制台窗口的 WebView2 开远程调试端口，可用 Chrome DevTools 连 `127.0.0.1:9333` 查 DOM / 抓截图 / 看 console |
| `http://127.0.0.1:8080/?overlay=1`             | 用普通浏览器预览「运行管理」浮层的排版（无 js_api，只填样例数据，按钮不生效）                                             |
| `CUKTECH_APP_DATA_DIR` / `CUKTECH_APP_LOG_DIR` | 换数据/日志目录（跑测试环境时用，避免动到正式数据）                                                             |
| `CUKTECH_WEB_INDEX`                            | 指定首页文件；`cuktech.py` 在 import 上游 server **之前**自动设好（打包后上游那套路径推算会错位）                      |

日志里这几行能一眼看出内置控制台是否正常：

```

[http] GET /console.js?v=...                   ← 页面来取浮层脚本了
[http] GET /__overlay?p=...                    ← 页面脚本真的跑起来了（探针）
[web] WebSocket 已连接 <- 127.0.0.1            ← 实时通道通了

```

## 常见问题

**托盘里找不到图标？** 点任务栏 `^` 展开隐藏图标，把闪电拖到常显区。

**双击图标没反应？** 说明已经有一个在跑 —— 它会把你已有实例的面板叫到前面（单实例互斥）。

**卡片跑哪去了？** 它是「固定在桌面」模式：按 `Win+D` 显示桌面就能看到（v1.3.4 起它不会跟着消失）。  
想让它一直浮在最上面，托盘右键 → 显示方式 → 悬浮置顶。

**卡片上写着「控制台未响应」？** 表示本地服务（`127.0.0.1:8080`）没跑起来，卡片退回了本地页面。  
直接运行 `%LOCALAPPDATA%\Programs\CUKTECH\CUKTECH.exe`（或开始菜单里的 CUKTECH），2 秒内自动恢复。  
（v1.3.5 之前这种状态会变成一块白底「未找到文件」，成因见 `版本更新说明.md`。）

**控制台窗口一片纯黑，但卡片上数据是好的？** 不是没数据、也不是配色问题，是  
WebView2 控件没建起来。**根因已在 v1.3.7 修掉**：控制台和桌面卡片原来共用同一个  
WebView2 数据目录，第二个宿主创建控制器会稳定报 `0x8007139F`；现在两者各用各的  
（`data\webview2-console` / `data\webview2-widget`）。另外还加了看门狗（重试 3 次 →  
必要时自动重启 → 托盘明确提示），防其它偶发故障。日志在 `logs\webview.log`  
（找 `WebView2 initialization failed`），详情见 `版本更新说明.md` v1.3.7 节。

**装完旧的两个计划任务还在跑？** 新版安装时会自动 End + Disable。真遇到两者并存（开机后起了两份、
互相抢蓝牙），在 PowerShell 里跑一句即可清掉：

```powershell
'CUKTECH充电器控制台','CUKTECH桌面组件' | ForEach-Object { Unregister-ScheduledTask -TaskName $_ -Confirm:$false -ErrorAction SilentlyContinue }
```

（v1.4.1 起根目录不再提供 `设置开机自启.bat` / `取消开机自启.bat`：那对脚本注册的是
**源码 venv** 的计划任务，和安装版的注册表自启项叠在一起正好就是「起两份」。）

**手机米家一直离线？** 正常。充电器只有一条 BLE 链路，电脑连着手机就连不上。
