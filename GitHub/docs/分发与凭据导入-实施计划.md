## 0. 先对齐术语

你说的「**硬件码**」，在代码里是 **三个值**，缺一不可：

| 口语叫法 | 代码里的名字 | 格式 | 作用 |
|---|---|---|---|
| 设备地址 | `CUKTECH_DEVICE_MAC` | 17 字符，`AA:BB:CC:DD:EE:FF` | 找到这台充电器 |
| 令牌 | `CUKTECH_DEVICE_TOKEN` | 24 位十六进制 | 米家云身份，MiOT 认证用 |
| 蓝牙密钥 | `CUKTECH_DEVICE_BLE_KEY` | 32 位十六进制 | BLE 会话加密 |

三者是同一次扫码一起产出的，**不存在只取其中一个的场景**。下文统一称为「凭据」或「三码」。

## 1. 现状梳理

### 1.1 现在取码的完整链路

```
双击 运行-获取Token.bat
  └─ cd tools\
     ├─ 探测 python → start watch_qr.py   （屏幕弹出的二维码窗口）
     └─ token_extractor.exe               （第三方，19.6 MB）
          └─ 交互：选 q → 扫码 → 手机点确认 → 屏幕打印设备列表
               └─ 你肉眼找 "CUKTECH" 那条，手抄 MAC / TOKEN / BLE KEY
                    └─ 手动编辑 app\.env 粘贴进去
                         └─ 启动程序
```

**问题在于最后两步**：靠肉眼找、靠手抄、靠手改文本文件。你自己用没问题，给别人用一定出错（抄错一位、少抄一段、找不到 `.env`、不会编辑）。

### 1.2 代码层面已确认的三个硬伤

| # | 问题 | 位置 | 后果 |
|---|---|---|---|
| **P0-1** | **你的真实凭据被打进了安装包** | `CUKTECH.spec` 的 `datas` 里有 `(HERE / ".env", ".")`；实测 `app\dist\CUKTECH\_internal\.env` 已存在，内容是你本机三码 | 任何人拿到 `CUKTECH-Setup.exe`，解压 `_internal\.env` 就能拿到你的设备控制权 |
| **P0-2** | **打包版读不到用户能改的 `.env`** | `cuktech.py:309` `candidates = [BASE / ".env"]`，frozen 时 `BASE = sys._MEIPASS`（PyInstaller 临时解包目录，只读、每次运行重建） | 即使把 `.env` 放到安装目录，程序也不读。所以「让用户自己填 `.env`」这条路在打包版**根本不成立** |
| **P0-3** | **没有「未配置」引导** | `ble.py:103` 缺 MAC 时静默回落占位符 `AA:BB:CC:DD:EE:FF` | 用户装完直接连不上，看不到任何原因，只会觉得「软件坏了」 |

> P0-1 的严重性取决于一件事：**根目录那 4 个安装包（v1.1.0 ~ v1.2.0）你有没有发给过别人？**
> 如果有 → 按「凭据已泄漏」处理（见 §2 P0-5）。如果只在自己机器上跑过 → 改掉 spec 即可，无损失。

### 1.3 其他分发风险（已核实）

- **`8080` 端口硬编码**：`autoport.py:82`、`.env.example` 都是 `127.0.0.1:8080`，无占用检测、无自动退让。8080 是很常见的被占端口（Tomcat、各种开发服务）。
- **取码工具给不到用户**：`tools/token_extractor.exe` 被 `.gitignore` 排除，也不在安装包里。用户装了软件也取不了码。
- **日志可能带凭据**：`cuktech.py` 把 stdout 全量写 `logs/console.log`，上游 BLE 报错时可能把 MAC/token 打出来。
- **安装包未签名**：38 MB 未签名 exe，SmartScreen 会拦，用户需要点「仍要运行」。

## 2. 分发前必须补的步骤（分级清单）

### P0 —— 不做就不能发

#### P0-1 把凭据从安装包里剥出去

**改法**：`app/CUKTECH.spec`

```python
# 改前
(str(HERE / ".env"), "."),
# 改后：只打模板，运行期由程序决定写哪
(str(HERE / ".env.example"), ".env"),
```

**同时加构建门禁**（`build_installer.py` 里，打包完成后断言）：

```python
# 伪代码
env_text = (dist / "CUKTECH" / "_internal" / ".env").read_text(encoding="utf-8")
for key in ("CUKTECH_DEVICE_MAC", "CUKTECH_DEVICE_TOKEN", "CUKTECH_DEVICE_BLE_KEY"):
    assert 值为空, f"构建中止：{key} 含真实值，拒绝出包"
```

**验收**：删掉 `dist\`、重新 `python build_installer.py`，用 7-Zip 打开 `CUKTECH-Setup.exe` 或解压 `_internal`，`grep TOKEN` 结果必须为空。

#### P0-2 配置迁到用户可写目录

新增 `app/desktop/credentials.py`，把「读配置」和「写配置」都收口到这里，**成为唯一出口**。

```
%LOCALAPPDATA%\CUKTECH\
├─ .env               ← 主配置（用户级、可写、卸载时可选择保留）
├─ .env.bak           ← 每次保存前的上一版
└─ credentials.json   ← 导入用结构化副本（可选）
```

**查找链改造**（`cuktech.py:load_env`）：

| 优先级 | 位置 | 用途 |
|---|---|---|
| 1 | 真实环境变量 | 排障临时覆盖（保持现状，`setdefault` 已实现） |
| 2 | `%LOCALAPPDATA%\CUKTECH\.env` | **新增**，用户主配置 |
| 3 | `%CUKTECH_APP_DATA_DIR%\.env` | 便携模式（U 盘） |
| 4 | `_MEIPASS\.env` / `app\.env` | 只作为**空模板兜底**，不得含真值 |

**实现要点**：
- `save()` 用「写临时文件 → `os.replace` 原子替换」，避免断电写坏
- 替换前把旧文件复制成 `.env.bak`
- `load()` 主文件解析失败（0 个有效 key）时自动回落到 `.env.bak` 并记一条日志
- 只写 `%LOCALAPPDATA%`，不写注册表、不写安装目录（可能是 `Program Files`，无权限）
- 权限收紧（可选但建议）：`icacls "%LOCALAPPDATA%\CUKTECH\.env" /inheritance:r /grant:r "%USERNAME%":F`

#### P0-3 首次运行凭据引导

**触发点**：`Manager.__init__` 之后、拉起子进程之前。
`credentials.is_configured()` 返回 False → 弹向导（模态），三个选项：

- **「我已经有码了」** → 走 §4 的粘贴导入（L2）
- **「我还没有，教我去取」** → 显示取码指引（图文：双击 `取硬件码.bat` → 扫码 → 回来粘贴）
- **「稍后再说」** → 进未配置状态，托盘图标置灰 + 气泡「设备凭据未设置，点击设置」，托盘菜单常驻「设置设备凭据」入口

**已配置但认证失败**（上游抛 auth 错）→ 托盘气泡「凭据可能已失效，点击重新设置」。

#### P0-4 前置格式校验

不要让错误凭据跑到 BLE 握手才炸。校验规则（`credentials.validate()`）：

| 字段 | 规则 | 归一化 |
|---|---|---|
| MAC | `^([0-9A-Fa-f]{2}[:-]?){5}[0-9A-Fa-f]{2}$` | 去分隔符 → 大写 → 每 2 位插 `:` |
| TOKEN | `^[0-9A-Fa-f]{24}$` | 转小写 |
| BLE KEY | `^[0-9A-Fa-f]{32}$` | 转小写 |

失败时给人话提示：「MAC 应为 12 位十六进制（如 `AA:BB:CC:DD:EE:FF`），你输入的是 15 位」。

#### P0-5 如果老安装包已经外发过

小米 token 无法「修改」，但**重新登录会签发新 token，旧 token 随即失效**。处置：

1. 让收到过包的人删掉旧包
2. 你重新跑一次取码（拿到新 TOKEN / BLE KEY）
3. 本机 `.env` 更新为新值
4. 后续所有包走 P0-1 改造后重新构建

## 3. 取码脚本方案（对应需求 2）

### 3.1 设计目标

1. **操作方式和你现在完全一致**：双击一个 bat、扫码、在同一个窗口里看到结果
2. 但结果**自动落盘**，不再需要肉眼找、手抄、手改 `.env`
3. 命令行也能直接调（给会折腾的用户 / 脚本化）

### 3.2 文件结构

```
酷态科充电器控制\
├─ 取硬件码.bat                  ← 新入口（保留 运行-获取Token.bat 作为兼容）
└─ tools\
   ├─ token_extractor.exe        ← 不变（第三方）
   ├─ watch_qr.py                ← 不变
   ├─ collect_credentials.py     ← 新增：捕获 / 解析 / 校验 / 落盘
   └─ out\
      ├─ raw-20261105-143012.txt ← 原始输出留档（排错用，含完整值，不自动清理）
      ├─ credentials.json        ← 机读，导入用
      └─ credentials.txt         ← 人读，可转发给朋友
```

### 3.3 命令行用法

```bat
:: 默认：弹二维码 + 跑取码 + 自动解析 + 写配置
取硬件码.bat

:: 只取码（二维码窗口自己已经开着）
取硬件码.bat --no-qr

:: 安静模式：只把 JSON 打到 stdout，不写配置（给脚本用）
取硬件码.bat --json-only

:: 不跑提取器，直接把剪贴板里的三码解析并保存
取硬件码.bat --from-clipboard

:: 等价于直接调 python
cd tools && python collect_credentials.py
```

### 3.4 `collect_credentials.py` 实现要点

**进程捕获**
```python
proc = subprocess.Popen(
    [str(EXE)], cwd=EXE.parent,
    stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
    stdin=None,                    # 关键：继承控制台，保留原有交互（选 q、选地区）
    bufsize=1, text=True,
    encoding="utf-8", errors="replace",
)
for line in proc.stdout:           # 逐行读
    print(line, end="")            # 实时透传，用户看到的和以前一样
    buffer.append(line)            # 同时累积给解析器
```
> ⚠️ 这里有个**待实测项**：`token_extractor.exe` 是 PyInstaller 打包的程序，stdout 经管道后可能整块缓冲（交互提示迟迟不出现）。
> M3 阶段第一件事就是实测。若出现卡顿，退路是改用 `--from-clipboard` 或纯 `set /p` 手工输入模式。

**三段式解析**

| 层 | 策略 | 说明 |
|---|---|---|
| A | 结构化匹配 | 按提取器已知输出找 `CUKTECH` 行及其 `MAC:` / `Token:` / `BLE key:` 后续值 |
| B | 特征兜底 | 全文扫：17 位 MAC 形态、恰好 24 位 hex、恰好 32 位 hex，各取第一个，且必须出现在同一段（±10 行）内 |
| C | 人工兜底 | A/B 都失败 → 提示「请把屏幕上的三行粘进来」，读 stdin 三行，再走一遍 B |

**校验与落盘**
- 归一化（MAC 补冒号转大写、两个 key 转小写）
- `credentials.validate()` 不通过 → 指出是哪一项、期望什么格式，不写盘
- 写 `%LOCALAPPDATA%\CUKTECH\.env`（原子替换 + `.bak`）
- 同时写 `out/credentials.json`、`out/credentials.txt`
- 屏幕只打**打码版**（`AB12****89EF`），完整值在文件里

**退出码**（供 bat 判断分支）

| 码 | 含义 |
|---|---|
| 0 | 成功，已写入配置 |
| 2 | 跑完了但没解析出三码 |
| 3 | 解析出来了但校验失败 |
| 4 | 找不到 `token_extractor.exe` |
| 5 | 用户取消 |

### 3.5 `取硬件码.bat` 实现要点

```
chcp 65001
setlocal
cd /d "%~dp0tools"

1. 检查 token_extractor.exe 是否存在      → 缺则提示 + 给下载地址
2. 三段式探测 python（沿用现有写法）      → 无 python 走纯 cmd 降级
3. 非 --no-qr 时 start /b watch_qr.py
4. python collect_credentials.py %*
5. 按退出码分支打印不同结尾
6. 成功时把配置路径和「现在可以启动软件了」打出来
7. pause
```

**无 Python 降级路径**（保证最差情况也能用）：
仍然跑 `token_extractor.exe`，然后 `set /p` 依次读 MAC / TOKEN / BLE KEY，用 `findstr /r` 正则校验长度与十六进制，直接 `>` 写 `.env`。功能等价，只是没人话级错误提示。

## 4. 导入机制设计（对应需求 3）

### 4.1 三层通道，按操作成本排序

| 层 | 场景 | 用户动作 | 实现 |
|---|---|---|---|
| **L1 同机直落** | 自己电脑上取码（最常见） | 双击 `取硬件码.bat`，完事 | 脚本直接写 `%LOCALAPPDATA%\CUKTECH\.env`，软件下次启动自动生效，**无需任何导入操作** |
| **L2 粘贴导入** | 已配置失败 / 换设备 / 码在别人那里 | 向导里粘一段文本 | 向导多行粘贴框 + 正则提取 + 实时校验 |
| **L3 文件导入** | 跨机（朋友帮你取码） | 把 `.txt` 拖进窗口 / 选文件 | 读 `credentials.json` 或格式宽松的 `.txt` |

**结论：L1 是主路径（90% 用户走这条，零导入操作），L2 是万能兜底，L3 是跨机补充。** 三者最终都调 `credentials.save()` 同一个函数，不会出现「三种格式互相打架」。

### 4.2 向导 UI 结构（`app/desktop/credential_wizard.py`，Tkinter）

选 Tkinter 的理由：安装器 `installer/installer.py` 已经用了，依赖现成，且不受 pywebview 生命周期影响。

```
┌─ 设置设备凭据 ────────────────────────────┐
│                                            │
│  ① 把取码窗口里的内容整段粘到这里：        │
│  ┌──────────────────────────────────────┐  │
│  │ name: CUKTECH 10 Ultra               │  │   ← 多行 Text，可粘贴任意格式
│  │ mac: AA:BB:CC:DD:EE:FF               │  │
│  │ token: 0123...                       │  │
│  │ blekey: 4567...                      │  │
│  └──────────────────────────────────────┘  │
│                                            │
│  ② 识别结果（自动填充，只读）              │
│  MAC      [ AA:BB:CC:DD:EE:FF ]  ✓        │
│  TOKEN    [ 0123abcdef...    ]  ✓ 24 位   │
│  BLE KEY  [ 4567abcdef...    ]  ✓ 32 位   │
│                                            │
│  [ 从文件导入… ]   [ 从剪贴板读 ]          │
│                                            │
│  ⓘ 取码方式：双击「取硬件码.bat」扫码      │
│                                            │
│           [ 取消 ]      [ 保存并重启 ]     │
└────────────────────────────────────────────┘
```

**交互细节（这是体验的关键）**
- `Text` 绑定 `<KeyRelease>` + 500ms 防抖 → `parse_paste()` → 回填三个只读 Entry
- 三个 Entry 无法满足校验时，「保存并重启」置灰
- 粘贴框里直接粘**整个终端输出**也能识别（含无关行不影响）
- 保存成功后调 `manager._restart_process()`（已有），避免用户自己找重启按钮
- 只粘贴了部分（比如只有 MAC）→ 明确说「还差 TOKEN 和 BLE KEY」

### 4.3 `parse_paste()` 解析策略

输入是任意文本，输出是 `dict | None`。按顺序尝试：

1. **带标签**：`(mac|token|ble\s*key|blekey)\s*[:=]\s*(\S+)`，大小写不敏感
2. **纯特征**：全文找「恰好 24 位 hex」和「恰好 32 位 hex」；MAC 优先匹配带分隔符的 17 字符形态，其次 12 位 hex
3. **避免误判**：24 位 hex 的候选如果同时能匹配成 MAC（12 位）的前缀，取更长的那条；多个同类候选且不一致 → 报「发现多个候选，请只粘贴 CUKTECH 那一条」

### 4.4 数据结构

`credentials.json`（schema 预留多设备）：

```json
{
  "schema": 1,
  "created_at": "2026-11-05T14:30:12+08:00",
  "source": "token_extractor",
  "devices": [
    {
      "name": "CUKTECH 10 号 Ultra",
      "mac": "AA:BB:CC:DD:EE:FF",
      "token": "0123456789abcdef01234567",
      "ble_key": "0123456789abcdef0123456789abcdef"
    }
  ]
}
```
当前只读 `devices[0]`，将来多设备不用改格式。

`.env` 保持现有格式（`CUKTECH_DEVICE_MAC=` 三行），因为上游 `ble.py` 直接读环境变量，不动它最安全。

### 4.5 安全约束

- 凭据**只**落 `%LOCALAPPDATA%\CUKTECH\`，不进 `data\`、不进 `logs\`、不进注册表
- 写日志前脱敏（P1-3）
- 向导回显和屏幕输出一律打码，完整值只在文件里
- 卸载时问一句「是否一并删除设备凭据」，默认**不删**（避免用户重装后又要重新取码）
- 不做任何网络传输

## 7. 需要你确认的 3 件事

**① 根目录那 4 个安装包（v1.1.0 / v1.1.1 / v1.2.0）有没有发给过别人？**
- 没发过 → 直接按 M1 改 spec，零损失
- 发过 → 按 P0-5 处理：重新取码、让旧 token 失效

**② 取码工具 `token_extractor.exe` 怎么交给用户？**

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 内置进安装包（推荐） | 用户零门槛，软件里一键打开 | 包体 +19 MB；需在关于页标注第三方来源与许可 |
| B. 单独下载 | 包体小 | 用户多一步，容易卡在「找文件」 |
| C. 不做分发，只支持「粘贴导入」 | 最省事、无合规负担 | 用户取不到码，等于不能用 |

**③ 要不要支持多设备 / 多组凭据？**
现在单组。数据结构我会按 `devices[]` 预留，将来加设备不用改格式 —— 但 UI 先只做单设备，可以吗？

## 8. 一句话总结

**真正卡住分发的只有一件事**：你的 `.env` 现在被塞进了安装包，而打包版又读不到用户自己写的 `.env`。把配置挪到 `%LOCALAPPDATA%\CUKTECH\.env` + 剥掉包内凭据 + 加一个首次运行向导，其余（取码脚本、粘贴导入）都是在同一套配置层之上加壳。

### 与计划不同的两处

1. **取码不用管道捕获**。实测 `token_extractor.exe` 原生支持 `-o out.json`，输出结构化 JSON
   （字段 `mac` / `token` / `BLE_DATA.beaconkey`）。于是改成 stdin/stdout 全继承、只读输出文件——
   交互提示和二维码完全不受影响，也不必猜测屏幕文本格式。计划里的「stdout 可能块缓冲」这个风险因此直接消失了。
2. **向导不用 Tkinter**。`app\.venv` 没有 tk（`build_installer.py` 里早有注释说明），
   改用项目已有的 pywebview，独立进程 + 独立 WebView2 数据目录（`webview2-wizard`）。
